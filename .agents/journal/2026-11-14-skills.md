# Project skills extraction — 2026-11-14

## Why this correction exists

The user asked where `.agents/skills/` were. The initial implementation had read the
prompt's reference lists and recorded access/results in `docs/research/`, but it had
not extracted that material into the repository as agent-loadable skills. The prompt's
closing instruction — “All those information supposed to be extracted to all this
codebase accordingly” — was therefore only partly satisfied. `.agents/` contained the
journal but no `skills/`.

## What was added

```text
.agents/skills/
├── react-feature-architecture/
│   ├── SKILL.md
│   └── references/{sources,component-shape,testing}.md
├── go-feature-architecture/
│   ├── SKILL.md
│   └── references/{sources,layering-and-idioms,testing}.md
├── security-audit/
│   ├── SKILL.md
│   └── references/
│       ├── sources.md
│       └── upstream/   # Cloudflare MIT subset at pinned revision + LICENSE
└── monolith-delivery/
    └── SKILL.md
```

OpenCode documents `.agents/skills` as a project-compatibility skill source, so these
are discovered automatically (ID = directory name). The index for humans and agents is
`docs/skills.md`; `AGENTS.md` now names each skill and when to load it.

### React skill

Adapts the four requested frontend references: mdskills.ai React tag, callstack
`agent-skills`, Ashwathvia's Medium architecture article (read in full through a normal
browser session after direct HTTP hit Cloudflare's challenge), and the patterns.dev
skills catalog. It records the repository's actual feature layout, public `index.ts`
boundaries, component order, state ownership, data flow, styling tokens, accessibility
states, Vitest/Testing Library patterns and the >80% gate. It explicitly rejects the
articles' mandatory TanStack Query/Zustand suggestion for this slice and explains why,
and maps every taken idea to a real file.

### Go skill

Adapts Leapcell's clean-architecture guide, Frederich Blessy's Go architecture article,
Reintech's 2026 Go structure guidance, CyberAgent/ABEMA's pragmatic layering and the
idiomatic-Go patterns skill. It records the inward dependency rule, per-feature
domain/repository/service/HTTP ownership, consumer-owned interfaces (the post feature's
`Authorizer`), `cmd` composition root, strict JSON, parameterized SQL, transactions,
fixed-width timestamps, sentinel errors, context and logging rules, and the three test
layers with the observed coverage numbers. It notes the deliberate deviation from flat
root layers (prompt requires feature-closed packages) and that `go-arch-lint` was not
added.

### Security skill

Vendors the Cloudflare `security-audit` skill (MIT, commit
`c1c8a8c1471069fb0e188eeaff69b8e8db6564a8`) with its license, companions, schema and
validators, and adds a project SKILL.md: modes, condensed six phases, artifact layout,
sandbox rules, this stack's boundary table, adversarial checks, the four run-1 records
and the known limitations. The durable run summary remains `docs/security-audit.md`.

### Delivery skill

Extracts the prompt's workflow rules that were previously only in AGENTS/README: the
`*.prompt.txt` → `*.plan.md` contract, one branch/worktree per plan, worktree removal
only after human merge confirmation, `{feature}: {description}` commits, journal
evidence standards, the full verification gate, push/remote-head verification, and the
Orca role boundaries including “Jev confidence is never permission”.

## What was deliberately not done

- No third-party React/Go skill text was copied; those skills are distilled guidance
  with citations and adaptations, because the references are articles/catalogs rather
  than redistributable skill packages.
- The Cloudflare skill is vendored only for the domains this monolith has. AI/LLM,
  desktop/mobile IPC, memory safety, RPC, cloud/IAM, data isolation and supply-chain
  companions were not vendored; the skill says to fetch them at the same revision if the
  product grows into those domains.
- No `.opencode/skills` duplicate was created: `.agents/skills` is the prompt-requested
  location and a documented OpenCode project source. Duplicating would create two
  sources of truth.

## Verification

- `find .agents/skills -name SKILL.md` → four skills.
- Each `SKILL.md` starts with YAML frontmatter containing `name` and `description`
  (required for discovery).
- Every path referenced inside the skills exists:
  `references/upstream/{SKILL.md,LICENSE,validate-coverage-ledger.cjs,validate-findings.cjs}`,
  each `references/*.md`, and the code files quoted.
- The vendored files are byte-identical to the pinned upstream revision; `LICENSE` is
  included and the revision is stated in three places (skill, sources, upstream README).
- `docs/skills.md`, `README.md` and `AGENTS.md` link the skills.
